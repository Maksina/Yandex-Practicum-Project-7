## Формат результата анализа golden_set.json

```json
{
  "answer_found": string,
  "completeness_score": int,
  "meaning_match": string,
  "explanation": string
}
```

- answer_found("да" / "нет"): Показывает, был ли в принципе найден какой-либо ответ
- completeness_score (число от 0 до 10): Числовая оценка полноты и точности ответа по сравнению с эталонным. Оценивается, насколько полно и корректно RAG-система воспроизвела ключевые аспекты эталонного ответа
- meaning_match("да" / "нет"): Определяет, соответствует ли смысл ответа RAG-системы смыслу эталонного ответа, даже если формулировки различаются
- explanation(строка): Краткое объяснение, на основании чего была выставлена оценка. Включает анализ ключевых различий между эталоном и ответом, а также обоснование числовых и булевых оценок

## Анализ логов

- Не всегда находятся релевантные чанки => необходимо улучшать и структурировать документацию, обновить алгоритм разделения на чанки
- Поиск в ChromaDB плохо понимает синонимы => необходимо пересмотреть алгорит поиска векторов, либо обогощать синонимами при индексации
- Фильтрация чанков слишком агрессивна => необходим пересмотр пост-обработки чанков
- LLM не всегда корректно обрабатывает релевантные чанки => необходимо улучшать промпт и рассмотреть более "умную" модель
